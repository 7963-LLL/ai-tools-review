Meta 开源 816B 的 Muse Spark Open：1M 上下文、42B 激活，两台 Mac Studio 就能跑

一、导语：美国最强开源模型，交到了开发者手里

Meta 把自家最强的一代模型开出来了。Muse Spark Open 总参数 816B、每个 token 只激活 42B，上下文窗口 1M token，原生吃文本、图像、音频、视频四种输入。它不是实验室里的权重文件：发布当日同步上架 Baseten、Fireworks、Groq、Modal、Nebius、OpenRouter、Together 七家推理平台，权重可从这里以外的 Hugging Face、Amazon SageMaker、Google Cloud Model Garden、Microsoft Foundry 直接下载。

更狠的是两个数字：Code Arena 的 WebDev 榜上，「Muse Spark Open (Max)」拿到 1511 分，是美国开源模型第一、开源总榜第 13；Artificial Analysis 智能指数 39 分，比第二名 Reflection Beam 的 30 分高出一整档。Meta 自己在博客里写得很直白：这是「迄今最强的美国开放权重模型」。

二、背景分析：开源这条线，Meta 不能丢

要理解这次发布，得先看 Meta 的处境。过去一年它的闭源前沿模型被 OpenAI、Google、Anthropic 反复压制，而 Llama 系的开源口碑又被 DeepSeek、Qwen、Kimi 这些中国团队一点点啃掉。今年 8 月，Meta 先用 Muse Glimmer 这个小号稠密模型探路，同时放出闭源的 Muse Spark 打能力榜——Muse Spark Open 就是这条产品线的第三步：把最强的那个规模，做成能下载的权重。

技术上也做了铺垫。同代的 Helion GPU kernel 已经在 SGLang 里跑了几个月，这次直接内置进开源版，官方给的数字是在 NVIDIA 与 AMD GPU 上取得 1.03–3.95 倍的 kernel 级加速、AMD MI350 上端到端提速 3%。换句话说，权重还没下完，推理栈已经替你调好了。

许可证也换了。这次不是 Llama Community License，而是新的 Muse Model License——条款细节尚未被广泛审读，但对商用部署的团队来说，这是发布当天最该先读的一页。

三、核心内容：816B 是怎么省着花的

架构是一套 62 层、隐层 8192 的稀疏 MoE：每层 256 个专家，每个 token 只挑 8 个，专家吃掉了全部参数的约 97%。所以显存里躺着的是整个 816B（BF16 safetensors 约 1.5TB），算力开销却按 42B 走。1M 上下文的代价也很具体：每个 token 的 KV cache 约 250KB，撑满 100 万 token 要 266GB——这也是官方推荐 BF16 用 4 节点 × 8 张 H200（TP=32）、而 NVFP4 量化版能压到单台 B200 节点的原因。视觉编码器 1.8B 参数，音频按每 80 毫秒一个 token 折算。

最出人意料的是端侧。Meta 用 MLX 张量并行把每一层拆到两台 Apple M5 Ultra Mac Studio 上，靠 Thunderbolt 5 的 RDMA 直连：各存一半权重、各算一半计算，权重全程不动，只在机器间传几十 KB 的中间结果。官方博客的说法很产品经理：

「我们相信未来属于所有人，其中也包括把先进模型跑在任何地方的自由，包括在自己家里。」
— Meta AI Research 官方博客《Introducing Muse Spark Open》

价格同样关键。OpenRouter 上输入 $1.25／百万 token、输出 $4.25／百万 token——比同级别闭源前沿模型低一个量级，而 1M 上下文的成本又被这个单价放大成实打实的工程决策。

四、各方反应：硬件厂抢 Day-0，榜单先打起来

硬件侧的反应最快。Intel 当天发布 Day-0 支持公告，用 vLLM 的 llm-compressor 加 AutoRound 算法，从原始 BF16 权重直接量化出 MXFP4（面向 GPU D 系列）和 INT4（面向 Xeon，仅权重量化）两套版本，配套 vLLM 与 SGLang 的上游支持。一个 816B 的模型能在发布当天跑上 Xeon，说明生态配合已经不是「等社区适配」的节奏了。

榜单侧的对照也很有意思。同一天 Artificial Analysis 放出 Reflection 首个开源模型 Beam 的评测：智能指数 30 分，美国开源第二，仅次于 Muse Spark Open 的 39。Arena 则把 Muse Spark Open 拉进 Agent Arena 让用户实测，Code Arena 的 1511 分紧随其后公布。三家独立评测机构在同一周给出互不矛盾的数字，这在这类「自评自夸」的发布里并不常见。

竞品的压力是另一面。DeepSeek 这两天发布 V4.1-Flash-1017，多个基准提升而 API 价格不变，紧接着开放了自研搜索 API；Google 的 Gemini 4 Argon 在 ARC-AGI-3 上刷到 97.5%。开放权重这条赛道，现在是美国的 Meta 对上中国的 DeepSeek、Qwen、Kimi、StepFun——而后者的成本优势依然明显。

五、深度解读：开源竞争的重心变了

第一层变化是「开源」的含义。过去开源模型的卖点是便宜、可微调；Muse Spark Open 直接把 1M 上下文、原生多模态、Agent 工具调用一起放出来，等于把「前沿能力」本身当成了开源标的。这会把下游应用的想象空间从「套壳聊天」推到「整套代码库级别的自主改代码」，也解释了为什么它首发就配套 Muse Code 这种端到端 agent 产品。

第二层是成本结构的重排。816B 的显存门槛注定大多数团队不会自建，真正的分发靠 OpenRouter 这类聚合平台和 Fireworks、Groq 这类专用推理商。结果是：权重开源了，生意却更集中在推理层。谁把 NVFP4、MXFP4 这些低精度路径调得最顺，谁就拿走调用量。

第三层是端侧的那条暗线。两台 Mac Studio 跑 816B，本质上是把「个人拥有前沿模型」从口号变成了配置清单。它对云厂商短期没有威胁，但对隐私敏感、离线可用的场景（医疗、法务、独立开发者）是一记实打实的开门锤；真正被削弱的，是那些只靠「模型能力」收月费的中层产品。安全侧，Meta 也明确说开源版「增加了额外的安全后训练」，并按 Meta Superintelligence Scaling Framework 逐项过阈值才放行——开放权重与安全的矛盾，它选择用「发布前评测」而不是「不发布」来回答。

六、总结

一句话：Meta 用 816B／42B 激活、1M 上下文、$1.25 的输入单价和两台 Mac Studio 的端侧方案，把「美国最强开源模型」这张牌打成了产品而不是姿态——接下来要看的是 Muse Model License 的细则，以及 266GB 的 KV cache 到底有多少团队真愿意付。

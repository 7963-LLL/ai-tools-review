11 小时、5000 人、两个版本号：Cursor 把 AI 编程工具的供应链风险摊开了

📅 2026-11-14📖 7 分钟行业 / 安全

11 月 13 日，Cursor 发布了那份拖了两周的调查报告，标题很克制：An update on our recent security incident。里面有几个数字值得记住——恶意扩展在市场里挂了约 11 小时，最多 5000 名用户可能下载到，受影响的版本号只有两个（2.1.312 和 2.1.313），不到 0.01% 的客户有 API 凭证暴露。整件事的起点不是 Cursor 自己的服务器，而是一把发给第三方的访问密钥。

这是 AI 编程工具第一次把完整的攻击链公开写出来。它同时暴露了一个很少被讨论的事实：这类工具的信任，最后其实是建在扩展市场的一层缓存上的。

一、背景：为什么偏偏是编程工具

Cursor 是过去两年增长最快的 AI 编程工具之一，用户每天把整个仓库、终端输出、API key 和长达数小时的 agent 会话记录交给它。这类数据的价值密度比聊天记录高一个量级：聊天里最多有几句抱怨，代码里有生产环境的连接串。

而它的分发依赖于 VS Code 扩展市场的镜像与缓存。为了保证全球下载速度，扩展包会被缓存在离用户最近的节点上。源站干净不代表缓存干净——这次出问题的正是缓存。Open VSX 官方源站自始至终没有恶意包，被投毒的是 Cursor 用于分发扩展的那层缓存。

二、攻击链：一把钥匙，四步走到底

Cursor 的调查把过程拆得很清楚，几乎没有留想象空间：

  • 第一把钥匙来自 Fireworks。攻击者拿到了 Cursor 发给 Fireworks 的访问密钥。这把密钥是 Fireworks 自己泄露出去的，权限是只读——足够读，不必写。
  • 只用只读权限就拿到了训练数据。那把密钥能读一个只读存储桶，里面是 Cursor 与 Fireworks 共享的 coding agent trace，主要是 2025 年的会话，来自未开启 Privacy Mode 的用户，用途是模型训练。少数 trace 里的凭证没有脱敏。
  • 从凭证横向到内部系统。攻击者用这些凭证进入了 Cursor 在用的若干 SaaS 工具，拿到归档的非生产代码仓库、部分客服数据与邮件、产品使用指标，以及一些用户发给客服的凭证。
  • 最后一步是缓存投毒。10 月 29 日，攻击者用从内部系统偷到的凭证，把 Anthropic Claude Code 扩展的篡改版本直接放进了扩展市场用来分发的那层缓存。Anthropic 没有发布过这个版本，这也不是 Anthropic 产品的漏洞。
「最多有 5,000 名在 10 月 29 日请求了特定缓存版本扩展的用户，可能收到了这个恶意构建。它在被我们移除前存在了大约 11 个小时。」
—— Cursor 安全事件调查报告，2026 年 11 月 13 日

三、损失到底有多大

Cursor 这次把「没有受影响」的部分也逐条列了出来，这在同类通报里不常见，但也正因为列得细，边界才看得清：

受影响的是 0.05% 以内用户的 coding agent trace（未开 Privacy Mode 的那部分）、不到 0.01% 客户的 API 凭证、部分归档的非生产代码仓库、部分客服对话，以及那 5000 名可能装到恶意扩展的用户。公司称已逐一通知，未收到通知即代表数据不在其中。

没有受影响的是：开启 Privacy Mode 的提示词与代码、客户代码仓库、生产系统、Cursor 客户端与其官方更新、发布签名密钥、其他任何扩展，以及从 Cursor Marketplace 下载的插件。Cursor 特别说明，它用另一套代码托管系统发布客户端，攻击者从未接触到那套系统。

四、各方反应与处置清单

Anthropic 这边的态度很明确：那个版本不是它发的，问题不在 Claude Code。Cursor 的处置则基本按「先切断、再重建」的顺序做完了一遍——把所有推理流量迁离 Fireworks、停用密钥、切断它对共享数据集的访问；按风险从高到低轮换全部暴露凭证，最后把内部系统在用的凭证也一并轮换，即便没有证据表明被用；重建整个扩展市场并逐个校验扩展真实性；给所有代码仓库加上密钥扫描；把生产基础设施整体重新部署，逐个服务复核后才恢复对外。

时间线也给了：10 月 29 日发现并下线，10 月 30 日发布安全公告与排查脚本，11 月 1 日之后攻击者再没有活动，11 月 13 日交出完整报告。外部取证团队介入。

行业层面的反应比公司声明更值得看。企业采购最先问的三个问题变了：你的 coding agent trace 会不会进训练集、扩展市场的缓存由谁管、供应商密钥泄露算谁的责任。这三个问题，Cursor 这次各答了一遍，答案都不算漂亮。

五、真正值得记住的三件事

1. 训练数据是负债，不是资产

整条攻击链的入口，是一个「为了训练模型而保留的历史 trace 桶」。这些数据在 2025 年产生，到 2026 年 10 月还在，还在被第三方读取。对用户来说，这意味着一句简单的判断：你今天没开 Privacy Mode 敲下的代码，可能在一年后仍然构成一个可被读取的存储桶。模型效果是当期收益，数据留存是长期负债，这次是负债先到期。

2. 缓存层是供应链上最便宜的攻击面

打源站要过审核、签名、发布流程；打缓存只要一把能写的凭证。攻击者绕开了 Open VSX 的全部校验，直接往离用户最近的节点塞包。所有依赖镜像、CDN、企业内网代理的软件分发体系，都有同一个洞——只是大部分公司还没被撞上。

3. 发给第三方的密钥就是你自己的边界

Fireworks 是训练与推理供应商，那把密钥是「只读」的。但只读意味着可复制：攻击者不需要写权限，只需要读走数据，再用数据里的凭证往上爬。把数据共享给第三方做训练，等于把安全边界画到了对方的运维水平上。

六、总结

5000 个用户、11 小时、两个版本号，数字不大，但它证明了一件不小的事：AI 编程工具的风险不在模型会不会写错代码，而在它为了训练和加速而保留、共享、缓存的那部分东西。下一步大概会有三件事发生——Privacy Mode 从「可选」变成默认、扩展分发开始做签名与来源校验、供应商密钥的权限被切到「只能读一个桶而且那个桶会过期」。这三件都不难，难的是在没出事之前做。
